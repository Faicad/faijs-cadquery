## 3. 方法

- **候选导出**：`run-cand` 全量 593 镜像 → **555 导出 / 38 失败**（每例 120s 超时，
  失败即删半成品 STEP，判卷分母保持诚实）。
- **判卷**：26 个分批 compare（`--only` 子串，模块桶 + test 名字母桶），每批
  ≤240s 预算，`out/report-0.35.8-<批>.json` 逐批存档，批后查 node 进程残留。
  驱动脚本沉淀为 `tests/rev-batch.sh`（含 MSYS2 下 `$!` 非 Windows PID 的
  进程树清理修复——v1 驱动曾因此泄漏 3 个挂死探针进程）。
- 挂死探针：`testParametricCurve` 单独 90s 预算探针确认 **0.35.8 下仍挂死**
  （0.33.6 时代 W2 留档的内核 curve-compound 布尔固有挂死延续），该 2 例从
  判卷集排除、判 ERROR 留档。

## 7. open-shell 比较器通道（r7/r8 解除，同日完成）

### 问题

2D 家族最后 2 条红（text r7/r8）在 2D 过滤解除后仍 FAIL——失败度量暴露机制：
**boolean 差 [0,0]、bbox ~1e-13，但 volΔ 11.6% / COM 4.98**。比较器包
（`step-compare.js`）取证：face-set（平面 face 集合）上
`kernel.getVolume/getCenterOfMass` 算的是代数体积——随 face 绕向 / STEP
writer 变化，r7/r8 即此伪影（CQ-OCP 与 occt-wasm 两个 writer 绕向不同）；
boolean cut 是真实几何计算且对 face set 有效。volume/COM 通道在该形状类别
上**病态定义**，FAIL 为假信号。

### 方案（tests/compare.ts，零容差改动）

- **自动路由**：双侧 solids=0 且存在 face → open-shell 通道（按形状类别，
  非手工豁免名单）；否则标准通道（else 分支与改动前逐字节一致）。
- **门控**：bbox（1e-3）+ boolean 差（0.1 mm³）——**容差值一个未动**，
  face-set 等价性由 boolean 差捕捉（与标准通道捕捉 solid-set 等价性完全同构）；
  face/edge/vertex 计数决定 PASS vs PASS-NT（非硬门，与标准通道同口径——
  首版误把 face 计数设为硬门，致 2 条 section PNT→FAIL 漂移，当日重判修复）。
- **审计**：report 条目带 `channel: 'open-shell'` 字段，volume/COM 仍记录。
  与 canonical-pose 注记通道同一红线原则：换判等通道 ≠ 松容差，全程可审计。
