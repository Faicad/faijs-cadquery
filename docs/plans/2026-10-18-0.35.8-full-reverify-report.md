## 3. 方法

- **候选导出**：`run-cand` 全量 593 镜像 → **555 导出 / 38 失败**（每例 120s 超时，
  失败即删半成品 STEP，判卷分母保持诚实）。
- **判卷**：26 个分批 compare（`--only` 子串，模块桶 + test 名字母桶），每批
  ≤240s 预算，`out/report-0.35.8-<批>.json` 逐批存档，批后查 node 进程残留。
  驱动脚本沉淀为 `tests/rev-batch.sh`（含 MSYS2 下 `$!` 非 Windows PID 的
  进程树清理修复——v1 驱动曾因此泄漏 3 个挂死探针进程）。
- 挂死探针：`testParametricCurve` 单独 90s 预算探针确认 **0.35.8 下仍挂死**
  （0.33.6 时代 W2 留档的内核 curve-compound 布尔固有挂死延续），该 2 例从
  判卷集排除、判 ERROR 留档。

## 6. include2D 2D 通道恢复（后续项 ②，同日完成）

### 机制

- 宿主 CLI 0.30.9+ G0-D 策略：2D-only 终端（面/边/线框）默认不导出，上述 32 条
  案例因此无候选 STEP、不可判卷。
- 逃生通路：宿主 `parseArgs` 的 `--include-2d` → `cliRun({include2D:true})`
  将 2D-only 终端写成 STEP；`tests/faijs-cli.mjs` 本就透传该参数，唯一缺环是
  `run-cand.ts` 不传 flag。
- 持久化：`tests/run-cand.ts` 新增 `INCLUDE2D_CASES`（34 个镜像 basename，
  沿用 `SELF_HOSTED_EXPORT_CASES` 先例——按 basename 键控、与 manifest 状态
  解耦，保证未来全量 sweep 持续导出）。**不全局开启**：对 2D/3D 混合终端
  案例会改变导出几何，扰动现行绿判卷集。
