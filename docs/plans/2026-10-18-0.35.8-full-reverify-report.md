## 3. 方法

- **候选导出**：`run-cand` 全量 593 镜像 → **555 导出 / 38 失败**（每例 120s 超时，
  失败即删半成品 STEP，判卷分母保持诚实）。
- **判卷**：26 个分批 compare（`--only` 子串，模块桶 + test 名字母桶），每批
  ≤240s 预算，`out/report-0.35.8-<批>.json` 逐批存档，批后查 node 进程残留。
  驱动脚本沉淀为 `tests/rev-batch.sh`（含 MSYS2 下 `$!` 非 Windows PID 的
  进程树清理修复——v1 驱动曾因此泄漏 3 个挂死探针进程）。
- 挂死探针：`testParametricCurve` 单独 90s 预算探针确认 **0.35.8 下仍挂死**
  （0.33.6 时代 W2 留档的内核 curve-compound 布尔固有挂死延续），该 2 例从
  判卷集排除、判 ERROR 留档。

按 mtime 每例取最新，10-12 方法学"fresh 覆盖陈旧档"）为基线：

| 集合 | 条数 | 结论 |

**32 条 2D 案例定性**：宿主 CLI"2D 终端过滤"策略（0.30.9 起，`81468c3` 宿主升级
引入）持续生效——这些案例最后一次判卷记录在 10-07 11:26 基线（19 PASS + 7
PASS-NT + 6 FAIL），此后（含 0.33.6、0.35.8）一直无 cand 配对。**不是 0.35.8
新回归**。逃生口 `include2D` 已存在（`tests/faijs-cli.mjs` 可透传），启用即恢复
判卷（后续项 ②，宿主侧策略决定）。

s3 cut 布尔、Fillet c TopoDS::Solid）：任何历史档案中均未判卷过——0.33.6 时代
即同态，非 0.35.8 回归，维持现状账目。
